## Executive Summary

Version 0.10.1 will completely rework the scheduled discovery and download system for monitored artists. This release addresses critical issues with the existing scheduling implementation and introduces a more robust, configurable, and reliable system for automatic video discovery and downloads.

## Current State Analysis

### Existing Issues (Problems to Solve)

1. **Dual Scheduler Confusion**
   - Both `SchedulerService` (legacy) and `EnhancedSchedulerService` exist
   - Unclear which is authoritative
   - Potential for conflicts and duplicate runs

2. **Inflexible Discovery Timing**
   - Hardcoded 24-hour minimum interval between discoveries
   - No per-artist customization
   - Cannot accommodate high-activity vs low-activity artists

3. **No Retry Mechanism**
   - Failed downloads are logged but not retried
   - No exponential backoff
   - Manual intervention required for failures

4. **Underutilized Celery Infrastructure**
   - Redis + Celery configured but not used for scheduling
   - Missing opportunity for more robust distributed scheduling
   - Thread-based scheduler less reliable than Celery Beat

5. **Limited Artist-Specific Configuration**
   - Cannot set different schedules per artist
   - Cannot set priority levels for different artists
   - All artists treated equally regardless of importance

6. **URL Resolution Latency**
   - Fallback to yt-dlp search adds significant delays
   - Should pre-resolve URLs during discovery phase

7. **No Health Monitoring**
   - Scheduler failures are silent
   - No alerting when scheduled jobs fail
   - Difficult to diagnose issues in production

```python
def discover_videos_for_artist(self, artist: Artist) -> DiscoveryResult:
    """Enhanced discovery with URL resolution"""

    # Check if discovery needed based on artist's custom interval
    if not self._should_discover_artist(artist):
        return DiscoveryResult(skipped=True, reason="Interval not met")

    # Discover videos from IMVDb
    videos = self._fetch_from_imvdb(artist)

    # NEW: Pre-resolve URLs using yt-dlp
    for video in videos:
        try:
            resolved_url = self._resolve_video_url(video.title, artist.name)
            video.url = resolved_url
            video.url_validated = True
        except URLResolutionError:
            logger.warning(f"Could not resolve URL for {video.title}")
            video.url_validated = False

    # Store videos
    stored = self._store_discovered_videos(artist, videos)

    # Update artist.last_discovery
    artist.last_discovery = datetime.utcnow()
    self.db.commit()

    return DiscoveryResult(
        artist_id=artist.id,
        discovered_count=len(videos),
        stored_count=len(stored),
        failed_count=len(videos) - len(stored)
    )

def _should_discover_artist(self, artist: Artist) -> bool:
    """Check if artist needs discovery based on custom interval"""
    if not artist.discovery_enabled or not artist.monitored:
        return False

    if not artist.last_discovery:
        return True

    # Use artist-specific interval (default 24 hours)
    interval = timedelta(hours=artist.discovery_interval_hours or 24)
    next_discovery = artist.last_discovery + interval

    return datetime.utcnow() >= next_discovery
```

#### 7. Download Service Enhancements

**File:** `src/services/video_batch_service.py`

**Changes:**
- Support for priority-based downloading
- Retry logic for failed downloads
- Batch status tracking

```python
def download_wanted_videos(self, max_videos: int = 10) -> DownloadResult:
    """Download wanted videos with priority ordering"""

    # Get wanted videos ordered by artist priority and video priority
    wanted = self.db.query(Video)\
        .join(Artist)\
        .filter(Video.status == VideoStatus.WANTED)\
        .filter(Artist.download_enabled == True)\
        .order_by(
            case(
                (Artist.priority == 'high', 1),
                (Artist.priority == 'medium', 2),
                (Artist.priority == 'low', 3)
            ),
            Video.priority.desc(),
            Video.created_at.asc()
        )\
        .limit(max_videos)\
        .all()

    results = []
    for video in wanted:
        try:
            result = self._download_video(video)
            results.append(result)
        except DownloadError as e:
            self._handle_download_failure(video, e)

    return DownloadResult(
        queued=len([r for r in results if r.success]),
        failed=len([r for r in results if not r.success]),
        details=results
    )

def _handle_download_failure(self, video: Video, error: Exception):
    """Handle download failure with retry logic"""
    download = self.db.query(Download).filter_by(video_id=video.id).first()

    if not download:
        download = Download(video_id=video.id, artist_id=video.artist_id)
        self.db.add(download)

    download.retry_count += 1
    download.last_error = str(error)
    download.last_attempt = datetime.utcnow()

    if download.retry_count < 3:
        # Schedule retry with exponential backoff
        backoff_seconds = 300 * (2 ** download.retry_count)  # 5min, 10min, 20min
        retry_failed_downloads_task.apply_async(
            args=[video.id],
            countdown=backoff_seconds
        )
        download.status = 'retrying'
    else:
        download.status = 'failed'
        video.status = VideoStatus.FAILED

    self.db.commit()
```
